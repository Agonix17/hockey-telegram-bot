# «Хоккей по-простому» — бот модерации, версия 1

Python-сервис принимает готовые черновики из Make, отправляет их владельцу в Telegram, публикует только после нажатия кнопки и сохраняет решения/оценки в SQLite.

## Что реализовано

- `POST /make/draft` — защищённый endpoint для Make.
- Черновики отправляются в отдельный канал `DRAFT_CHANNEL_ID`.
- Одобренные посты публикуются в `CHANNEL_ID`.
- Telegram-кнопки: **Опубликовать**, **Отклонить**, **Изменить**.
- «Изменить» просит прислать исправленный текст; бот отвечает моноширинным блоком для удобного копирования и повторно показывает кнопки модерации.
- После публикации бот просит оценить важность и качество текста от 5 до 1.
- Затем можно отправить примечание или нажать «Без примечаний».
- В SQLite сохраняются исходный и исправленный тексты, источники, решение, оценки и комментарий.
- Дубли с тем же `rss_guid` не создаются повторно.
- Проверка владельца по Telegram user ID; endpoint Make защищён Bearer-секретом.

## Важно перед запуском

1. Создать бота через BotFather и получить токен.
2. Узнать свой Telegram user ID.
3. Добавить бота администратором в **черновой канал** с правом публикации сообщений.
4. Добавить бота администратором в **чистовой канал** с правом публикации сообщений.
5. Указать `DRAFT_CHANNEL_ID` и `CHANNEL_ID` как `@username` или числовые ID каналов.
6. Сгенерировать отдельный длинный `MAKE_WEBHOOK_SECRET`.
7. Не отправлять токен бота, секрет или API-ключи в чаты и скриншоты.

## Запуск на Linux-хосте

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# заполнить .env секретами
set -a
source .env
set +a
python main.py
```

Откройте порт 8080 через HTTPS reverse proxy (например, Caddy/Nginx). Polling Telegram работает исходящим соединением; Make должен иметь доступ к `https://ваш-домен/make/draft`.

## Черновой канал

Кнопки находятся под сообщением черновика в `DRAFT_CHANNEL_ID`.
После нажатия **Изменить** отправьте исправленный текст новым сообщением в этот же канал.
Бот сохранит его как новую версию и отправит повторный черновик с кнопками.

Telegram не передаёт боту личный ID автора обычного сообщения в канале, поэтому бот принимает исправление только в черновом канале и только после нажатия **Изменить**. Не отправляйте в этот момент другие текстовые сообщения до исправленного поста.

Проверка состояния:

```text
GET /health
```

## Настройка HTTP в Make

После финального JSON Parse добавьте HTTP `POST` на:

```text
https://ваш-домен/make/draft
```

Headers:

```text
Authorization: Bearer <MAKE_WEBHOOK_SECRET>
Content-Type: application/json
```

JSON body:

```json
{
  "post": "{{финальный JSON.post}}",
  "source_url": "{{финальный JSON.source_url}}",
  "title": "{{RSS.title}}",
  "reason": "{{финальный JSON.reason}}",
  "facts": "{{Sonar JSON.facts}}",
  "sources": ["{{Sonar JSON.sources}}"],
  "rss_guid": "{{RSS.rssFields.guid}}"
}
```

В Make выбирайте токены через mapper, не набирайте `{{...}}` как обычный текст. Формат массива `sources` следует сопоставить с реальным типом выходного поля Sonar; если Make отдаёт массив, передайте весь массив, а не оборачивайте его второй парой квадратных скобок.

## Первая версия: ограничения и безопасное поведение

- Бот не публикует автоматически; публикация происходит только по кнопке.
- Отклонённые посты остаются в базе для будущего анализа.
- Оценки не переобучают модель автоматически; это редакторская статистика для последующего улучшения промпта.
- SQLite подходит для одного постоянно работающего экземпляра. Для нескольких реплик потребуется внешняя БД.
- Бот предназначен для личного чата администратора; действия иных пользователей игнорируются.
